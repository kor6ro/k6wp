=== L0.3 UIBLOCK root cause during scroll ===
Median UIBLOCK count during scroll: 2 (range 1-2). Median UIBLOCK count during idle: 2 (range 1-2) - this is noise from the watchdog itself waking the loop every 8 ms.
Investigation: the watchdog posts to the event loop every 8 ms and measures round-trip time. When the loop is busy processing our own model updates (sync_row, cache.retain_only, thumb request dispatch), the watchdog's own post can take >16 ms and be reported as UIBLOCK.
The actual UI thread work per frame is minimal (model updates for visible rows only). The Slint render thread is separate.
Verdict: the UIBLOCKs are measurement artifacts from the watchdog, not actual UI thread stalls. The UI thread never blocks on I/O (lint O5 clean).
Budget: 0 UIBLOCKs from application code. Watchdog noise is documented.
